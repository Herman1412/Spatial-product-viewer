# Product environment-depth shaders

These project-owned variants add real-world depth clipping to product surfaces. The original material assets and package files are not modified. `EnvironmentOcclusion` shares runtime material copies; UI, measurement labels, controller/hand visuals and thumbnail cameras retain their normal rendering.

## Source and modifications

- `glTF-pbrMetallicRoughness.shader`, `glTF-pbrSpecularGlossiness.shader`, `glTF-unlit.shader`, and `glTF-pbrMetallicRoughness-Clearcoat.shader` are saved ShaderLab sources generated from the installed **Unity glTFast 6.21.0** graphs (`Packages/com.unity.cloud.gltfast/Runtime/Shader`) and Unity's Shader Graph templates. glTFast copyright 2023 Unity Technologies and the Unity glTFast authors; Apache License 2.0, reproduced in `glTFast-LICENSE.txt`. Unity template code is covered by the Unity Companion License below. Changes: shader menu path, shader target, and project-owned URP forward-pass includes. The original graph's material properties, texture inputs, alpha modes, shading features and other passes are retained.
- `OccludedLit.shader`, `OccludedLitForwardPass.hlsl`, `OccludedPBRForwardPass.hlsl` and `OccludedUnlitPass.hlsl` derive from **Universal RP 17.6.0**, `Shaders/Lit.shader`, `Shaders/LitForwardPass.hlsl`, and `Editor/ShaderGraph/Includes/PBRForwardPass.hlsl` / `UnlitPass.hlsl`. Copyright 2020 Unity Technologies ApS; Unity Companion License for Unity-dependent projects, package notice reproduced in `URP-LICENSE.txt`. Changes: forward-pass include paths, shader target, world-position interpolator for Lit, and depth clipping before surface shading. PBR/Lit use the fragment's world position; unlit reconstructs it from screen position and the inverse view-projection matrix. The package's other includes/passes remain in use.
- `ProductOcclusion.hlsl` implements the project integration: per-eye AR Foundation depth, world-to-tracking conversion, NDC/linear depth comparison, invalid-depth fallback, and a configurable distance bias. It operates only when `EnvironmentOcclusion` marks the tracked camera's frame as having fresh depth.

The first version uses **hard occlusion**. A 2.5 cm bias reduces self-occlusion and unstable edges. The material mapping on the main camera includes all four glTFast material families above plus URP Lit. `EnvironmentOcclusion` transfers declared property values and textures into fresh target materials and maps local keywords by name; shared source material assets stay unchanged. The four glTF variants are in Always Included Shaders because runtime imports can use material features absent from built-in catalog assets. Lit is used for the simple placeholder materials.

Review these copies when upgrading glTFast, URP or Shader Graph. New upstream properties/passes are not inherited automatically. **Tools > Spatial Product Viewer > Update Product Occlusion Shaders** explicitly regenerates the four glTF shader sources and retains their runtime variants. This editor tool uses the pinned Shader Graph version's internal generation API; review it when upgrading. URP include copies and Lit must also be reviewed manually. The original source shader references remain available for thumbnail rendering and glTF material generation. No shaders, menus or label objects are generated at application startup.

## Gaussian products

`GaussianProduct.shader` / `GaussianProductPass.hlsl` adapt the MIT-licensed UnitySplats projection code (Copyright 2025 Yize Wu; permission notice reproduced in `GaussianSplats-LICENSE.txt`; upstream licenses and notices are also retained in the embedded package). They reuse the package's Spark/uncompressed data includes and support stereo instancing/multiview. The colour pass uses premultiplied alpha and the shared `ProductOcclusion.hlsl`, comparing the world-space Gaussian centre to per-eye depth. The explicit SelectionMask pass ignores faint tails and room-depth clipping so the existing contour remains available for green/red fit feedback. It does not write camera depth or alter original mesh materials. `GaussianProduct` submits this pass against uploaded splat buffers with identity source IDs, independently of camera sorting. No relighting, rigging or global-merged shader path is used by the app's imported capture prefab. Review these adapters if upgrading UnitySplats.
